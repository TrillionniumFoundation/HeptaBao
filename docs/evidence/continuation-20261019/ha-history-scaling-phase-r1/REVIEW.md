# Native HA history scaling: bounded phase observations

The actual b24 product with the three-line private seed-log creation correction stopped at 48 of the original 98 LAN requirements. Its first nine 2 MiB history writes succeeded, with the mutation duration growing from about 2.6 seconds to 12.5 seconds. The tenth mutation returned 503 after about 14.0 seconds. The original source receipt and all three hosts' shutdown observations remain unchanged. This delta does not declare that failure fixed.

The source shows repeated complete history work. Publication opens the prior committed closure, authenticates the candidate's complete typed graph, and sends the complete ciphertext closure to voters. Voter transfer uses three leaves per fresh TLS frame, including the local vote, and existing leaves still undergo actual exact readback plus file and directory fsync. The installer authenticates the received complete graph, visits every object, and performs full local materialization before and after its root CAS. The new traces separate these phases so the next physical run can determine which path consumes the observed growing latency. The current evidence establishes growth with retained history, but it does not yet measure an individual phase or prove a nested quadratic loop within one write.

Only the existing private-ha-forward-diagnostic feature emits the observations. The original actor, source generation, immutable file custody, full typed graph, ReadIndex, quorum and fsync calls remain in place, in the original order. No request deadline is created, captured afresh or extended. The phase guard reports an unfinished phase on error unwind; it cannot change the original returned result and ignores a stderr write error. All diagnostics are absent when the feature is disabled.

The 16 stable phase labels are listed in phase-observation-scope.json. The outer Service spans overlap their inner publication or installation spans, so their durations must not be added together. The fields contain only phase names, elapsed time and public size/generation counts. No payload, actor material, credential, file content or key is emitted. A completed phase is not a successful HTTP request, durable outcome or test pass. Existing original deadline checks after the diagnostic points remain authoritative.

The before blobs were checked against the exact committed R6 manifest. Removing only the added instrumentation reconstructs every original source file byte for byte. No product optimization, skipped read, new cache, changed protocol, changed deadline or changed test selector is included. Local rustc and rustfmt were unavailable, so compilation and physical phase evidence remain to be obtained by root. The original 55, 31 and 98 denominators and budgets are retained.
