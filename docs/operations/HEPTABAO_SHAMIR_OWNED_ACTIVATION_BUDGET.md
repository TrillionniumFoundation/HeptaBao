# Shamir process-owned activation budget

A newly elected ordinary Shamir node can have the committed Raft root while its admitted local application still owns the preceding root. The process-owned activation worker must publish authenticated durable B and the recovery index before reporting readiness.

The HTTP listener already passes its configured work budget into `start_ha_activation_worker_with_budget`. Previously the worker used that value only for wrapper backends and reduced ordinary Shamir activation to the one-second read-only idle-maintenance budget. The existing Shamir precommit guard requires more than one second remaining before B, so every ordinary worker pass necessarily withheld B. Health also keeps a one-second budget and therefore cannot repair this liveness gap. A physical A55 three-host run elected Pocket4 after killing X230, but its application remained unavailable with repeated `R990_SHAMIR_B_PRECOMMIT=insufficient_original_budget`.

Every process-owned activation now uses the configured budget captured before the single writer try-lock. The worker starts no queued pass and refreshes no phase, owner receipt or unseal deadline. A failed quorum observation still admits no state. The worker may occupy the service writer for its existing configured upper bound; HTTP writer admission retains each independent request deadline and returns unavailable when that deadline expires. Worker shutdown wakes the thread and joins only its current bounded pass.

Health remains one second. The deployed HTTP configuration remains twelve seconds, peer forwarding eight seconds, and the durable-B precommit guard remains strictly greater than one second. No readiness, quorum, durable integrity, rollback or original-owner deadline check is removed.

Regression coverage uses a real committed V5 record root and Shamir durable store: without any HTTP or new unseal request, the configured worker must catch up from A to B. Separate real-quorum isolation verifies bounded one-second request writer admission, bounded shutdown, no queued activation after drop, and unchanged durable generation and unseal nonce. The original-owner deadline and low-budget publication regressions must continue to pass. Physical qualification retains the complete original 69-check runner, mutations attempted once, three independent LAN hosts and original server budgets; partial checks never grant full OpenBao replacement.
