# X230 two-bundle source-only stage

This is a proposed controller and a separately bound current-576 example. No Native call, Python compile, source checkout, binary transfer or test has run. The final Linux build is currently failed at its default libtest compilation, so this packet is not permission to stage a product successor.

The single BINDING block contains the exact candidate and transport facts. The controller retains twenty complete helpers and the original child cleanup block from the historical Linux receiver. Its old seven-artifact product admission is removed explicitly because this source-only operation transfers two Git bundles and no binary or qualification receipt.

The 235,828-byte stdin fits the unchanged 262,144-byte carrier limit. The complete Native request envelope is 267,126 bytes because it also carries the 30,059-byte inline controller; these are distinct sizes. The controller reads only the fixed old base and its newly created owned tree. It never substitutes an alternative base, fetches a network repository, changes a product branch or resets the historical checkout.

The template is intentionally unbound. Execute neither template nor bound example without root's exact GO. Future commits require new actual bundle bindings, byte pins, request/key and source review. The static verifier performs no Python or host operation.
