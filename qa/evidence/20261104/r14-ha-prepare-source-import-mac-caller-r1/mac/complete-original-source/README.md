## Explicit practical limits

The two current captures are bounded point-in-time observations, not a transaction or cross-agent atomic snapshot, and not a whole database backup. SQLite immutable disables locking/change detection; stable metadata and empty/absent sidecars are fences only, not transaction proof. Same runtime qualification covers Python/_sqlite3/source SHA and versions, not the full dylib graph.

Installed code pins cover the selected actual entrypoints/metadata from the known receipt, not every transitive package module. Sandbox read permission for finite actual harness roots enables real loader dependencies; it does not qualify every file under those roots. Current five-agent raw/effective semantics are asserted by actual SDK calls when run, not assumed by materialization.

Launchctl registration/path/arguments and PID birth are sequential observations; a label operation does not provide atomic PID custody. Launchctl text grammar and the full lifecycle are still source-only. A missing/unknown report, incomplete response, unconfirmed close, unexpected label/birth, source drift or late completion cannot produce success. Failed cleanup records unresolved lineage rather than inferring that bootout or process exit closed every child. Original failed generations remain untouched.
