## What remains unbound for production

No accepted production address/cluster identity/namespace/CA/leaf/RoleID/SecretID issuer or delivery-path binding is present in the current caller. `bootstrap_api` initializes a new isolated server and writes fresh fixture credentials; these values cannot fill production fields. The actual endpoint, CA, role and secret-source values that eventually matter must come from a current explicit registration; the plan contains no guessed private path.

The policy generated by the current fixture allows reads only for its seeded canonical documents, create/update in its Mac inbox, and token self lifecycle routes. A later production policy needs its own exact canonical bytes/hash and readback. The native route selector remains separate from authentication and must not be broadened to accept unsupported JWT, Kubernetes, OIDC or MFA state. For a child namespace, the actual catalog/incarnation/role profile and real handler authorization still apply.

Renewal is a precise remaining measurement gap: the current token-lifecycle helper records a successful renewal response, but it does not compare an independent pre/post token expiry or lease duration. A production verification source should bind those returned observations to the same token/namespace and original request clock before calling expiry extension proven. Revocation's204 plus a subsequent403 is already represented in the isolated source graph, but still needs the actual production credential/policy binding.
