# AuthBus P01: exact archived mappings and executable public projection

This package executes the next source step using eight already archived public originals. It does not query a host. The projector consumes one exact, pinned stdin document, verifies every source by byte count, SHA-256 and Git blob, and emits the complete service, rollback and follow-up read mappings. The actual local execution exited 0. All original input and output bytes, the harness and executor response are retained.

## Concrete next readsets

The first readset contains nine exact public startup, backup and hold receipt paths and their original whole hashes. Each proposed read is file_info followed only after successful regular-file, size, version and hash admission by bounded version-pinned binary reads of that same path. Each is at most 2 MiB, with 64 KiB chunks, and stops on drift or unknown. These are nine registration/hold evidence references, not nine backups. None has been submitted by this projector.

The second readset contains two limited dependency contracts: the actually observed Mac gateway plist plus its service-env file, and the one historically observed X230 config pathname for metadata only. A future semantic reader must expose only proven path arguments and must not evaluate a shell, environment file or arbitrary argv. New paths are not guessed from unresolved arguments.

## Reversible new registration proposal

The package proposes three new roots under the actually evidenced Mac, ROG and Pocket homes. They are new intended names, not observed existing directories. Any existing entry must refuse create-only publication. Actual parent identities, addresses, cluster IDs, issuer receipts, CA and leaf certificates, RoleIDs and SecretIDs remain unbound until real secure issuance and exact review. No loopback fixture value fills a production slot.

The ten explicit dependency steps bind accepted product and member identities, create only the new roots, issue an independent CA and member leaves, initialize the actual new cluster once, freeze and read back per-host policy, obtain per-host AppRole issuance, verify real token lifetime and revocation, change four client connection fields under CAS, prove actual persistence/restart/inverse for that host, and register and restore the new encrypted backup dependency. Policy paths must come from the installed AuthBus operation closure and actual grants. Canonical grants and inbox proposals stay distinct. Unsupported native-profile routes stay refused.

Only address, caFile, roleIdFile and secretIdFile in the AuthBus connection config are eligible for a separately authorized future change. Models, provider, refresh, quota, enabled, order, caches, hold directives and service definitions are not changed here. A public endpoint projection is insufficient to restore an exact private predecessor; actual inverse requires a private original capsule and the exact expected-after hash. There is no automatic service start or hold release.

## Renewal evidence and backup scope

The existing isolated fixture's HTTP 200 renewal is not evidence of lookup-self TTL or expiry extension. A separate next increment must observe the same token before and after renewal, record actual renewable/TTL/expiry semantics, and retain the revoke plus revoked-denial chain without replay. This package does not modify the frozen fixture or its deadlines.

Historical capture and restore dates and hosts remain their original meanings. The known encrypted restore chain concerns one historical 23-file / 7-database / 6-auth-store capture, not a current Mac backup qualification. Newly issued production state needs its own source-bound backup registration and restore proof.

## Execution and limits

The projector imports only hashlib, json, sys and time. Its candidate code opens no files, runs no SQLite or subprocess, uses no network and mutates no services. The local harness supplies in-memory stdin and captures stdout. The harness alone reads and writes local public artifacts. The explicit new local cap is 5 seconds through flush, with 524288-byte input/output ceilings; it does not replace any host capture, query, consumer or manager budget. Actual execution used 328295 input bytes and emitted 104595 bytes.

All host readsets and production actions remain source-only. The current Mac registry-harness predicate diagnostic is a separate exact request under separate root review; it is neither executed nor re-authorized by this package. Existing failures and UNKNOWN records are preserved.
