# Fixed public live sandbox-denial observation — SOURCE ONLY

This is a new public experiment, not a replay. It creates two new public HOME directories and copies the exact original 6,909-byte profile. No SDK, JavaScript, provider or credential input is requested. Five fixed executable identities, including the already observed log binary, are held and hashed before any child.

A small Python carrier is the direct child that will attempt Node. It reports a fixed ready PID and waits for one byte. Original capture_child records actual parent/session/user/birth. The parent freezes a predicate using that actual reserved PID's complete node(PID) token, starts one log stream and records a bounded queue interval. It then writes one G byte once. The carrier emits a fixed release marker and calls execve for sandbox-exec -> Node --version with the exact closed environment. This establishes source/marker evidence of an exec attempt; it does not independently sample the final kernel image. The carrier closes stdin after the gate; no private stdin is supplied.

The new fixed coordinator uses original Commands initialization/public accounting and the byte-exact original WNOWAIT capture/exit/once-stop functions; synchronous Commands.run cannot overlap the two children and is not called. There are at most two primary direct children. Existing bounded ps helpers inside custody/cleanup are explicitly additional. The application records five input FDs, ten HOME FDs and five parent pipe FDs; Popen/loader internal temporary descriptors are not claimed individually traced. Any incomplete acquisition, pipe registration or cleanup remains UNKNOWN.

35/45/60 second ceilings are unchanged. Capture work stops by START+17, reserving two original TERM1/wait5/group3 cleanups before START+35. Independent controller child deadlines do not rely on the tool's timeout interpretation. Log begins before the gate. Both exited children remain unreaped during capture; log cleanup is attempted before Node cleanup. A failed log cleanup is never represented as a known close merely because the Node closes.

The actual help permits --level debug, --style ndjson, --predicate and --timeout; no show-only flags are used. The token filter is intentionally narrower than all Node/system events. A normally running log process and the 0.25-second queue interval are not subscription acknowledgements. Delays, dropped/redacted rows, reporter differences and formats can hide a deny. Rejected JSON/non-JSON rows keep fixed type/reason records; they are not called headers, statistics or harmless. No unknown raw text, key names, resources or hashes are exported. Only current-PID/time/closed-origin records with explicit deny syntax may yield bounded public operation/resource projections. Zero matches never establishes no denial or a root cause.

## Isolation boundary assessment

The profile is generated by the QA materializer (198feabe7aef20b302e5989fd72e99e0bc0d36c3, consumer_profile) and enforces production-data denial, fixed fresh credential inputs, phase-only writes and one owned loopback port. It is not a product API requirement shown by these sources. Nevertheless it is the current validation contract: fresh HOME, cwd and an explicit environment do not provide equivalent access control against SDK/plugin code. A separate unsandboxed SDK process would also lose the same active global registry / same-instance assertions. A future trusted public bootstrap that applies the same kernel policy in the same process before any SDK/private read would require a concrete new binding/API and real denial witnesses; none is present or qualified here. This experiment changes no business boundary and grants no SDK baseline.

No slot has been initialized and no Native call has been submitted. The complete source, exact request and journal must receive root's own review/GO before execution.
