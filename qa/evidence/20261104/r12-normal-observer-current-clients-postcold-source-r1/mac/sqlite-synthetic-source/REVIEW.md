# Mac immutable capture prerequisite — new source-only package

This package does not authorize production capture or launchd work. No Mac,
ROG, SQLite production file, provider or service was accessed while preparing it.

## Exact scope

The synthetic entry runs once under the same actual Python executable intended
for later capture. Its seven owned cases use the actual held-FD immutable-query
library: absent sidecars; zero-length WAL and fixed SHM; nonempty WAL refused
before connect; any rollback journal refused before connect; oversized primary
row refused; held-inode drift refused; and an actual read-only connection that
refuses a write to an owned fixture. Unsupported Connection.setlimit or SQLite
read-only WAL version is a refusal, not a fallback.

The public final stdout, actual authoritative exit zero, completed cleanup and
same original 45-second deadline must all agree before any proof is accepted.
The proof binds whole source SHA, actual Python executable SHA, _sqlite3
extension SHA, versions, and the five source inputs. No expected result is
substituted for an actual proof. The full stdout becomes a fixed raw-byte proof
input only after independent terminal review.

Only ROOT/capture-sqlite-synthetic-r1 may be created, under held T5 anchors and
the actual diskutil UUID check. The exact observed mount is root-owned mode0775;
the synthetic library admits this one mount metadata shape under that caller
guard. All descendant inputs are held through no-follow parent FDs. The
production /Users traversal has no such exception. All SQLite setup mutations
are to these new owned fixtures. There is no production database experiment.

## Deadlines and ownership

The synthetic component has a new shared 45-second success limit; it is not a
relabeling of an old runtime. Its only child is fixed diskutil, at most its
existing 30 seconds clamped by that shared deadline. The generic foreground
command helper uses the already reviewed retained-child WNOWAIT chain and one
TERM1/wait5/group3 cleanup, with PS at most4. Cleanup may finish after the
success deadline but cannot turn that into success. There is no retry.

Source/runtime hashes are public code reads, each bounded to64MiB and subject
to the same original deadline. They are explicitly separate from the library's
8MiB aggregate current-input/returned-row cap, and do not claim SQLite page-I/O
measurement. All private inputs and public child output remain independently
bounded. Production capture still requires a separately reviewed sandbox
caller, fixed synthetic proof bytes, and private publication under the original
capture deadline. Those outer modules are not supplied or qualified here.

The library adds an explicit cancellation callback so a signal deferred during
FD registration cannot be silently ignored by subsequent reads/queries.
Public code FDs are registered/closed under the same signal protection. No
code removes SQLite limits or changes the original source-row bounds.

## Evidence limitations

The root's earlier AST/25 typed report tests, six custody components, and the
peer's16 observer ledger mocks remain separate. This package does not rerun or
expand those suites. A local source-only AST command was attempted; the cloud
exec service rejected process creation with No such file or directory.
Therefore these three new source files have not yet received an actual Python
AST result. No source code was executed and no files were written by that
failed check. Root may parse the fixed files before approving the one owned
synthetic run.

Current capture remains bounded point-in-time observation. Immutable SQLite
skips locking and change detection. Matching before/after names and metadata
does not establish a transaction snapshot, cross-agent atomicity, whole DB
backup, or absence of an undetected concurrent writer.
