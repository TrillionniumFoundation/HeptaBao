# Mac self-renewal lookup evidence — source-only increment

This independent proposal closes the missing lookup evidence around the already frozen self-renewal request. It does not change the failed runtime, rerun capture, grant host execution, resolve the selected harness owner, or bind a fresh executable candidate. BINDING_READY is deliberately false. The original paths and all original product, proof, policy, role, deadline and size constants are retained only to make the source delta reviewable; they are not a new dispatch contract.

For each of the two existing phases, the original single owned token-file read moves to immediately after the phase and before existing canonical/inbox operations. A new lookup-self records actual TTL/expiry/renewable. Existing KV observations then occur. The original unassigned 403, empty-body renew-self, revoke-self 204 and revoked-access 403 remain, with one new independent lookup after renewal. Raw ID, token and accessor stay private. The actual accessor is also added to the existing secret-literal publication guard.

A legal 200 renewal whose observed expiry is unchanged is explicitly not extension evidence. Both unchanged and decreasing expiry are preserved as observations and the original revocation chain still completes. Only positive observed expiry change for the same token/accessor qualifies. The final evidence requirement runs after the original two inverse phases and original validation, so failure to demonstrate extension does not suppress the required inverse operations. It is a known missing-evidence failure, not a claim that a legal HTTP 200 is invalid. There are no sleeps, retries, new token reads, role edits, token issuance changes or budget increases.

The selected pure checks executed eight mock groups using the exact three proposed functions. The whole source was parsed and compiled only. No complete module, network request, SDK selector, SQL operation, child, actual credential or host API ran. The old 23 other top-level functions/classes, including HTTP, capture, manager context and source readers, are byte-identical. The original base packet and all previous failed/unknown jobs remain immutable.

The local staging mechanism initially added one extra trailing LF to the two scratch source copies. A byte-only check detected it before parsing or running selected functions. The exact pinned candidate and base were restored by removing that one verified extra LF. Both observations are preserved; the source strings and source diff were never changed by this local staging correction.
