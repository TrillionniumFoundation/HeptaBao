# Exact Mac source recovery

The retained Mac normal builder and normal TLS observer were recovered from their original external T5 control directory. Each complete UTF-8 response was independently checked against its previously recorded SHA-256. The read tool reports independent file snapshots; this package does not claim an atomic pair snapshot.

The 5,531-byte builder is preserved unchanged. Its Cargo subprocess keeps the original 1,800-second budget and verifies actual default features and release artifact metadata. A new launcher will bind the strict-qualified unified source and the already demonstrated release build-directory cache lock without changing these builder bytes.

The recovered observer is the prior executed e4 normal-wire observer (59,402 bytes), not the unavailable later compatibility observer r2. The unexecuted launcher r2 and compatibility observer r2 remain explicitly unrecovered. Reconstructed controls receive new revisions and hashes.

No product build, server startup, credential mutation, traffic cutover, or old-service deletion was performed by this recovery.

The four files under `control/` are the exact closed input set for the source-only stager. The new launcher takes no arguments and pins physical source `70714605c39014bea93545f7f6aa4217d2a23544`, tree `ef0ae63704a06b7dda1038e02abcc3233a2a438f`, the original strict-Clippy receipts, fixed Python/Cargo/rustc bytes, and the actual Cargo release-lock probe. The prepared source is not yet syntax-tested or executed.

Preparation has a 300-second absolute deadline. It holds the existing source release build-directory lock through APFS `cp -cR` and full distinct-inode checks, with no copy fallback. A symlink or special entry in this unproved cache layout is an explicit refusal. This lock is not a claim of whole-cache or host reservation. The original 5,531-byte builder remains unchanged and owns its original 1,800-second Cargo timeout, normal feature/profile checks, and actual artifact receipts.

A narrow process-creation wrapper registers each real child before delivering a pending signal. It does not change the original builder argv, environment arguments, session choices, or waits. Cleanup may signal a group only while its direct child remains unreaped. Once the original builder has reaped a leader, later observed group members are reported as a failure and are never signalled using the old group number. A failed clone is cleaned up before releasing its source lock. No product server is started by this launcher.

This package provides a new revision; it does not reconstruct or claim the unavailable earlier launcher hash. A successful normal build would remain an integration candidate with the known compatibility gaps, not full OpenBao replacement qualification.
