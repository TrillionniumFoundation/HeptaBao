# ReadIndex 验证器准备检查点：尚无真实 HA 资格

此目录保存新的验证器源码、原始父流程、独立审阅差异，以及已经实际执行的本地控制测试。所有实际产品入口仍为 `DRAFT_ONLY=True`。它不是 Mac/ROG/Pocket4 HA 或生产替换的成功证据。

当前本地控制分别为：响应验证 42/42、原始日志验证 35/35、本地 TLS 传输控制 11/11、历史证据连接的合成模型控制 13/13。不同组的结果不相加为产品检查数。历史模型使用人为构造的 owner 与日志，只有本地私有文件读取、写入和 fsync 是实际执行；它不能证明任何真实主机、凭证、ReadIndex 或选主行为。

新的实际历史适配器保留原有 98 项直接 HA 检查、30 项官方历史检查和 6 项 owner 检查。父函数的 AST 已逐项比较；除明确增加观察 profile 字段和固定源码/控制文件绑定外，原有请求、写入、停机与快照流程不变。原严格历史传输文件必须取得运行时 SHA `71a81748…` 的原件；已读取的 Git 文件 `15355994…` 是另一个版本，不能替代它。

按原始流程成功路径逐调用计数，共 20 次进程启动：19 次 native ON 和最初 1 次 standalone OFF。新验证器要求全部历史启动一一对应。追加的证据整理池在第一次产品执行之前固定为 360 秒，包含最多 20 次各不超过 15 秒的关闭日志读取及本地原件核验、关联和最终 fsync。它不给原有 1800 秒整场预算、45 秒清理预算、5 秒停机预算和 15 秒 HTTP 预算额外时间。

首次历史模型控制的 9/10 失败与当时源码仍保留：删除日志中的 terminal 后，已有序列缺口校验比预期的缺 terminal 校验更早拒绝。后续保留该拒绝，并增加序列连续但缺少 terminal 的对抗模型。归档脚本首次误把自己源码中的私钥标记字面量当成真实私钥行，该本地打包错误及原脚本也已保存。

归档不包含合成本地 TLS 私钥或大量可重建的模型文件。实际原始 Mac API 捕获仅表示当前控制文件已传送以及已有原任务的已知状态：新 42 项控制的原作业终态尚未取得，当前 Mac 35 项和 11 项尚未启动，不能用本地结果填充这些空缺。

完整冷备恢复、真实多节点 HA、AuthBus、真实客户端迁移、切流与旧版删除仍需各自的独立实际证据。
