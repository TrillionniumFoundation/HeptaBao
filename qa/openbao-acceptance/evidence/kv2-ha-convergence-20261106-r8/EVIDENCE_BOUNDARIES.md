# Evidence handling and claim boundaries

The package keeps actual failures and success observations as separate generations. Preparation, local focused guards, code-only diagnostics, and runtime service acceptance have distinct scopes. A successful diagnostic that expects a refusal is not a successful projection or product operation.

Original native terminal and complete stream wrappers are preserved where their payload is public. Native private payloads remain outside this Git evidence tree. In particular, root tokens, unseal shares, private keys, credential rows, and content fingerprints of private inputs are excluded. Native start requests containing private metadata or command fingerprints are represented by explicitly labelled allowlisted projections.

Raw launchctl inspection and some macOS logs contain inherited environment or attribution fields. Their public forms explicitly identify their projection boundary; they are not described as lossless raw originals. Actual kernel denial lines and exact queried service identity are retained in the dedicated diagnosis package. Native metadata raw JSON is preserved before numeric parsing; Python verification handles large inode and nanosecond integers without JavaScript numeric round trips.

Checks of complete local public payloads against independently fetched native Git tree blob size/SHA, plus recomputation of every directory tree object, establish the frozen evidence content. They do not claim a second independent network download of every blob or make product correctness claims.

The service candidate remains uninitialized at the final manager reconciliation and stopped repair. No init request was issued. The installed LaunchAgent plist still has RunAtLoad/KeepAlive, and bootout is not persistent disable; the evidence proves exact absence at observed reconciliation points. Any future launch or init requires a new admission of current state, legitimate macOS permission, and a new resume generation. The original create-only manager/init entry must not be replayed.

No root token, unseal share, or init nonce exists from the failed service attempt. This statement does not erase previously created source-backup encryption material or the newly generated TLS keys; those are separate key roles. Empty remote custody directories do not constitute transferred shares or verified independent backups.

Neither a current credential baseline nor a successful projection recreates missing historical OpenBao KV2 versions. Prior 34 MiB isolation results, SDK subsets, same-machine test voters, and a dev-mode OpenBao reference do not satisfy formal KV2, real multi-host HA, AuthBus, per-host migration, or cleanup gates.
