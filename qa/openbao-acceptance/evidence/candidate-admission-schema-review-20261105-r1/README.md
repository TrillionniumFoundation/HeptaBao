# 正式 KV2 准入与恢复：仍关闭的验证器草稿

本包保存 51 份精确原文件和内部清单。它是准入验证器及本地控制检查的审阅记录，不是产品运行结果。四个资格/产品入口均为 `DRAFT_ONLY=True`，新的真实 13 作业正例尚不存在，正式 DR25 实际执行次数仍为 0。

原有 181 项/平台、完整 31 项和独立恢复 25 项的分母与预算保持不变。新观察器要求每个平台另有 16 项，并把一个真实执行器中的两个派生 suite 保持为同一作业。后续图要求依次为 13 个原始作业、加 full31 后 14 个、加四个恢复阶段后 18 个；只有实际原请求、worker、终态、完整输出和子进程记录闭合后才能准入。

本次重点修正 Mac 字段差异：原 Mac 正常构建回执没有 `cargo_lock_sha256` 或 `source_before` 字段。验证器改为明确读取同一已验证提交的当前冻结 `Cargo.lock`，并保留该证据的真实范围；不会补造旧回执字段。Linux 仍核原构建的前后锁文件记录。

包内保留早期控制 harness 的真实失败、修正后的 8/8 以及作业图 inventory 的 9/9。本地模型检查没有实际新候选执行器，也没有启动产品。原始 48 成员索引、独立 root 审阅和三个补充索引/结果均按原 SHA 保存；没有递归收集模型数据目录或私钥。

## 离线复核

将归档、`MANIFEST.public.json`、`result.public.json` 与 `verify_archive.py` 放在同一目录，执行：

```sh
python3 verify_archive.py
```

它核对归档和全部成员原字节及四个关闭入口，不解包执行、不启动产品、不访问主机。源版本 R10 的实际整体构建已经失败；本包绝不把源码审阅、本地控制通过或归档成功换算为构建、KV2、HA、AuthBus、切流量或替代资格。
