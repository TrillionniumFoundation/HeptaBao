# Recovery-only preparation for the initialized fixed-slot fixture

This package is prepared source. It has not run on the Mac and does not qualify the coordinator's remaining business workflow.

The original single request was reconciled to native job `1a1b3e976fc-fc05-8575`. Its full request, complete source and complete stdout were recovered and pinned. The authoritative result was failed with `fixture_original_t5_mutable_directory`, after strict TLS health returned 501 and the sole initialization returned a complete, privately durable 200 response. No unseal or Node coordinator worker was dispatched. Every original Rust process, command, stream and explicit descriptor closed. The original native request lacks an idempotency-key field: the association to the sole recorded launch uses the complete source, executable, argv and timeout, not a fabricated native key observation.

The failure arose at a QA directory-identity check. Canonical initialization publishes its staged database directory through rename; retaining the original empty directory's inode across that successful operation is incompatible with that behavior. The old pre-initialization inode was not separately recorded. The later read-only preflight `1a1b40a9813-fc05-85f4` did record the current ROOT/data/log identities and verified the original fourteen events, private initialization material and empty, undispatched Node state. That observation does not rewrite the failed attempt.

This successor uses the same existing T5 store, private HOME fixture, CA, leaf certificate, server key, original initialization response and eleven original Node assets. It creates only a new `custody-recovery-r2` directory, plus the previously undispatched private role and worker-plan files. The new directory is a once barrier; a failed or unknown attempt is not replayed by deleting it or choosing another key.

Admission binds the original complete request/source/stdout and fourteen events, then retains their exact file generations and held parent identities. It requires the observed published data-directory inode. The first new strict TLS health response must show an initialized, sealed store. The API explicitly rejects initialization routes and the `init` category before recording or dispatching a request. The original root token and unseal key stay private. There are no new cryptographic-generation commands, production credentials, provider requests or service-registration changes.

The remaining stages use two new owned Rust generations and the original initial/cold Node worker bytes. They exercise the concrete fixed-slot protocol, including local receipt interruption and cold reconciliation. This is not a simulated network packet loss. The original request, stream, handle and process custody rules remain in force. Unknown outcomes retain their original private journal and stop subsequent business operations.

The recovery attempt has a distinct, explicitly named execution key and its own 600-second parent budget, 120-second phase budgets and 630-second supervisor. It does not extend or relabel the failed R1 budget. Its source admission is at most 20 seconds inside that new parent budget. Coordinator operations remain at most 30 seconds, strict Node requests 15 seconds, Python business requests 10 seconds and readiness 15 seconds. Node receives the parent's absolute monotonic deadline.

The local result contains twelve targeted checks: the actual public originals satisfy the exact admission prefix; changed job/source, unknown worker state, incomplete closure, incomplete or nondurable initialization and an extra request are rejected; four ways to address initialization are rejected before a journal or network action. These checks read no private original material and make no network call. They are not a Mac execution result or a replacement for the remaining real coordinator qualification.

Root must review the complete frozen launcher, its source and API differences, the original-job provenance and the new recovery plan before a single actual execution is authorized. The original failed attempt and its complete immutable evidence remain unchanged.
