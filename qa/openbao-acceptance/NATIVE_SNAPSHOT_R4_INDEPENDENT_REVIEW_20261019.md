# Independent source review of native snapshot clock restoration R4

Reviewed the frozen `numeric-witness-r4` overlay SHA256 `9b8176206bad0be0389d3530aee1c79df2107fe013376a35b46f61e4df9a2d58`, based on commit `36ee52ace6351dc92bea5accadabee32e5803c17`, tree `ef9a9c4783d39deec49d39c16edee3767823a3ae`. The adjacent JSON pins every reviewed file. This is a read-only source review, not a compilation, test result or native acceptance receipt.

## One concrete defect found and corrected before freeze

`project_v6_restore_before_install` raises the prepared state's generation to `max(live, source) + 1`. The previous `restore_v6_prepared_gate_impl` rollback guard consequently inspected the derived generation and could not reject an older original archive when its caller supplied `allow_rollback=false`. The frozen R4 now checks `prepared.size.generation`, which remains the authenticated original archive generation, before any object staging. Non-projected behavior is unchanged. The existing HTTP Service explicitly supplies `true`, so its authorized restore behavior is preserved. No second concrete product blocker was found in this review.

## Evidence supporting the new implementation

**Archive identity and clocks.** `prepare_incoming_v6` first authenticates the whole pack, validates archive root/epoch, retained V5 source and active cursor, then materializes the entire typed graph from that same prepared archive. It inherits only the existing Auth and Engine monotone clocks and then runs the original protected successor/schema/credential/retirement checks. The target generation and replay epoch are separately checked as one greater than the maximum of original archive and live facts. Archived generation/epoch remain explicit response facts; a new checkpoint is never labeled as the old archive.

**Typed graph projection.** `project_snapshot_native_root` keeps KV1 and requires the projected KV2 descriptor serialization to equal the original graph. It serializes the five opaque owners; after substituting back only Auth/Engines and epoch, the entire encoded root must equal the authenticated archive root. It then independently materializes the resulting root using staged owner objects and the same affine archive for original payloads, and runs `check_native_installed`. A clock update cannot silently round or rewrite retained KV data. The existing cursor's `advance` preserves the authenticated V5 source digest/generation while binding the derived V6 digest, new epoch and publication generation; it is validated again against the retained source.

**Affine and durable state.** `project_prepared_v6_state` retains the source's actual `Arc` instance and original complete `RestoreFrontier`; it does not prepare a replacement from a new live service identity. Its derivation digest binds live/source/target generation and epoch, both actual root values and every replaced resource value. The new snapshot, single derivation ledger and checkpoint journal use the same final generation and epoch. Old live and archive acknowledgements are retired. Root and active cursor are sealed into the same prepared bundle and consumed by the existing `restore_prepared` transaction with target-bound FileIntent, backend CAS and unknown-outcome fence. No independent root/epoch sequence was added.

**Immutable ciphertext.** Existing archive resources are re-read from the original authenticated member and must match the requested owner plaintext. If a derived owner already exists in the actual live durable map, R4 validates its locator/store/length, reads an actual profile-bound immutable pin, decrypts and compares the plaintext, then reuses those exact ciphertext bytes and registered slot. It does not re-seal equal plaintext at an existing address or repair corruption. Before root publication, the original restore staging path reopens all selected pins and requires their bytes to equal the authenticated incoming/projected ciphertext bit for bit. Original object count/byte/component/journal limits remain in force.

**Original request custody.** Full gates continue to use the same `SnapshotTransferPlan` Actor, namespace/path, initial observed time plus actual elapsed time, absolute deadline, base state identity, activation, live seal and stop/failure state. Bounded I/O checks do not grant Actor authority. No replacement Actor, request retry or new request budget was introduced. The three Auth/Engine clock helper gates retain both `fixture-native-v6-service` and the existing `experimental-native-v6-ha` configurations.

**Independent fixture observations.** The new post-commit callback exists only under `cfg(test)`, accepts `&Service`, is one-shot and clears on drop. Its test captures the actual admitted Auth bytes/floor before restoration, then checks the actual durable selected root and its Auth digest immediately after successful commit, before an outer terminal clock/audit write could conceal an omitted floor. The subsequent real cold Service unseal is inspected before its outer terminal clock update, then ordinary history/negative-zero/witness reads still execute. A separate existing test now covers an older archive lacking the protected token-precision owner: copying a later clock must still return 400 and preserve the live value/activation and valid issued credential.

The live two-process migration controller does not require `restored_generation == archive generation`. It requires a successful restore and then actual cold API/history and lossless witness checks. Witness publication generation remains a strictly typed per-read source fact, with no invalid cross-request equality requirement. The R4 source-generation/new-checkpoint response therefore fits that controller without weakening its predicates.
