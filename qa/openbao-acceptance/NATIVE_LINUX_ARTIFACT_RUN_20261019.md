# Execute the original main native artifacts on X230

`native_linux_artifact_run.py` is an additional controller. It does not edit or invoke `native_candidate_host_run.py`, Cargo or rustc. Its `pack` subcommand runs on the actual Linux producer after the original host runner has completed. Its `execute` subcommand runs the transferred artifacts on the separately identified X230. Source commit/tree and original producer runner SHA remain explicit arguments; the actual transfer controller SHA is separately recorded. A later QA/controller commit must not relabel the product artifact cohort.

## Producer custody

Supply the original completed producer summary and its exact SHA, complete manifest/source and target directory. The tool takes a **shared, nonblocking lock on the original target lock file** and requires its recorded producer PID/source/output to match the completed run. It never rewrites the lock, stops a build or copies an artifact from a filename glob. It finds exactly one server and one peer libtest path from their real compiler logs, verifies every original list/run log/header/selector and requires them to name the same compiled artifact. The successful server build row binds the actual server path/hash/size. The complete product source is independently verified before and after packing.

The new private capsule contains the unmodified three executable files (`server`, `peer`, `server-bin`), original summary/manifest, relevant original compiler/list/test/build logs and producer ELF/loader metadata. Each binary is copied and hashed in 1 MiB chunks, up to **2 GiB per artifact**, with canonical path, owner, no writable group/world mode, one link, NOFOLLOW and unchanged inode/size/time identity checks. Destination creation is exclusive. Existing outputs and partial capsules are never overwritten. The packer's JSON receipt is written only after the closed inventory is complete. Keep the resulting capsule SHA and independently compare observed artifact hashes with already retained producer observations before transfer. Do not reuse this target for a newer build until the old capsule is complete.

## Executor command

Transfer the complete flat capsule into a **new private, owned, canonical directory** on X230, preserving file modes (`700` executables, `600` metadata) and byte contents. Preserve the producer capsule SHA from its actual completion output. No transport or remote operation is embedded in this tool. Run the `execute` CLI from the JSON template after replacing only the null fields with actual observed host paths/hash. The expected X230 hostname from its existing actual receipt is `qian-ThinkPad-X230`; recheck it before submission.

The executor verifies the full product manifest/tree and closed capsule. `/usr/bin/file`, `/usr/bin/readelf` and the actual GNU loader `/lib64/ld-linux-x86-64.so.2 --list` establish x86-64 ELF identity and resolve **real executor libraries**. Private RPATH/RUNPATH and unresolved dependencies are refused. Producer and executor library identities are recorded separately; they need not have equal hashes. Existing observations show main requires GLIBC through 2.39 and the prior X230 identifies glibc 2.39, but only this actual loader/run establishes portability. No LD_* override or private loader shim is supplied.

Every original group is listed again directly with its transferred libtest. The exact name inventory and count must match the producer's list before execution. All **17 groups / 55 tests**, original selectors, `--nocapture --test-threads=1 --color=never` and **1800 s per command** remain intact. There is no retry, skip-to-pass or timeout extension. Cargo's package-root working directory is recreated from the independently verified executor source. Producer paths embedded at compile time are never rewritten; a source-path dependency failure remains visible. Failed groups retain their actual partial pass/fail counts, rather than counting the whole group as passed or losing observed successful cases. A separate newly owned, uninitialized server process gets one complete CA/SNI/leaf-pinned loopback TLS health read, then is stopped and reaped. That probe is distinct from the 55-case denominator and performs no init or credential operation.

The summary keeps producer=main and executor=X230, `compiled_on_executor=false`, exact actual executable/source/loader identities, original producer status, every command/log, fixed denominator and stopped owned process evidence. Final source/capsule/system dependency checks are mandatory. Exceptions retain failed or unknown state; only newly created child process groups are stopped.
