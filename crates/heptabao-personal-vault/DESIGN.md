# Personal vault candidate

Unix-only client-side vault, separate from HeptaBao service credentials. The server stores only an opaque encrypted envelope. No real credential adoption is qualified.

Uses existing locked `ring` 0.17.14 AES-256-GCM and Argon2id v1.3 (64 MiB, t=3, p=4, bounded exact format) plus CSPRNG. A random 256-bit data key is independently wrapped by a password-derived key and by a random 256-bit recovery key. The recovery key is returned only to an explicit new private file. Passwords and item bodies enter via bounded stdin JSON, never argv or environment. Uses the mature argon2 0.5.3 crate with RFC 9106 second recommended parameters.

`heptabao-vault <absolute-root> <init|put|list|get|totp|generate|delete|backup|restore|export|import|health|change-password>` accepts command JSON on stdin. Standard output is only metadata/status. `get`, `totp`, `generate`, `export` and initial recovery material require an explicit `output` path in a private directory; create-only prevents accidental overwrites. `backup` copies ciphertext. `restore` validates a backup with password or recovery key and writes a fresh destination vault. CLI processes unlock for one bounded operation and clear buffers when they exit. SDK sessions use a monotonic absolute expiry and an explicit lock method. Every operation refuses expired sessions; an idle SDK caller must schedule `lock()` or drop the session to clear memory at the deadline. The browser adapter owns this timer. The borrowed `get` result is trusted local caller access, not a revocable remote capability.

The existing descriptor-anchored `ExclusiveDirectory` fences cooperating concurrent processes. Processes running under the same OS account that ignore this protocol remain trusted; the file lock is not a sandbox against them. Existing envelope digest and expected revision are checked before mutation; writes use private temporary files, fsync, rename, directory fsync. Reads reject symlinks, hardlinks, non-private files, unknown schema, unbounded KDF/input and corrupt AEAD. The authenticated header includes format, vault identity, revision and key wrapping parameters. Entry records use login, note and api types, with opaque secret fields never included in lists/debug output. TOTP accepts strict RFC 4648 Base32 and RFC 6238 SHA1/SHA256/SHA512 vectors via ring HMAC.

The format cannot detect restoring a complete old ciphertext envelope without an external trusted monotonic anchor. Backup-based device recovery requires separately retained recovery material or password. Lost devices already holding plaintext cannot be retroactively erased. No browser autofill, Android provider, Passkey, sharing, or physical multi-device synchronization is claimed by this crate.

The Argon2 work area and application-owned secret buffers are zeroized. This is not a guarantee that OS swap, core dumps, allocator history, third-party cipher internals, or explicitly exported copies contain no plaintext. Hardware-backed key storage and memory locking are not implemented. Password rotation rewraps the data key; it does not invalidate previously copied backups or the separately retained recovery key. CLI initialization publishes the recovery document in a separate private directory before initial ciphertext. If the recovery output conflicts or cannot be published, no vault is committed. A later ciphertext publication failure can leave an unused recovery document; it is retained and the caller must inspect state. SDK `create` returns the recovery key directly and trusts its caller to retain it.
